# LocalAI Cowork v0.3.3

v0.3.3 fixes native Windows AI Sandbox setup and local-daemon pipe contention, and adds an installed-app release gate for the complete setup and execution path.

## Highlights

- **Reliable Windows setup:** Sandbox account hardening now decides success from the final verified group membership. Benign Windows cleanup return codes no longer abort a setup whose account and group are already in the required non-administrator state.
- **SID-based workspace access:** Installer and shared workspace ACLs use resolved local SIDs instead of account names. Per-run isolation uses an unresolvable restriction SID written through native Windows ACL APIs, avoiding both `icacls` name-resolution failures and invalid desktop-token capability combinations on fresh machines.
- **Per-user runner access:** Before starting the isolated process, the app validates the sandbox credential and grants its dedicated local group read/execute access only to the installed runner executable, so per-user installations work without exposing the surrounding profile.
- **Policy-compatible PowerShell:** Native sandbox commands use PowerShell's encoded command channel instead of unsigned temporary `.ps1` files, so enforced `AllSigned` policies do not break a fresh installation.
- **Cold-start profile initialization:** The sandbox runner loads the dedicated account's Windows profile and supplies the standard profile environment paths. The installed release gate allows the one-time profile and PowerShell initialization to complete on a genuinely fresh account.
- **Contention-safe local daemon:** Windows keeps a pool of named-pipe listeners ready for parallel startup reconciliation, while the desktop bridge waits through transient daemon startup and `ERROR_PIPE_BUSY` states instead of failing after one second.
- **Actionable diagnostics:** Setup failures identify whether UAC result handling, DPAPI protection, credential persistence, capability-seed persistence, or the setup marker failed.
- **Visible setup errors:** The Settings view keeps the actionable setup error visible while refreshing readiness instead of replacing it immediately with the generic not-configured state.
- **Installed sandbox release gate:** The Windows installer smoke now performs first-time setup, repeats setup to verify idempotence, validates protected setup state, and executes a workspace write under the `LACoworkOnline` identity.
- **Pre-publish candidate verification:** A non-publishing Windows workflow builds an exact `origin/main` commit, runs the installed sandbox gate on a fresh runner, and retains the candidate installer only as a short-lived test artifact.

## Installation and update integrity

- Windows: `LocalAI-Cowork-Setup-x64.exe`
- Linux: AppImage, DEB, and RPM packages
- In-app updates: signed Tauri updater artifacts and `latest.json`
- Verification: `SHA256SUMS`, CycloneDX SBOM, third-party notices, provenance, and GitHub attestations

> Windows publisher notice: Unless Authenticode credentials are configured for the release workflow, Windows may display “Unknown publisher.” Verify `SHA256SUMS` and the GitHub artifact attestations before running the installer. In-app updater artifacts are independently protected by the mandatory Tauri updater signature.
