# LocalAI Cowork v0.3.4

v0.3.4 fixes persistent local runs and restores Codex compatibility for fresh installs and upgrades from v0.3.1 through v0.3.3.

## Highlights

- **Persistent runs validate correctly:** New installations create a stable RFC 4122 v4 user ID instead of the legacy all-zero-version placeholder rejected by the desktop contract.
- **Existing data is repaired automatically:** On daemon startup, affected run records are migrated to the installation's persistent user ID before the app reads them.
- **Codex works with the bundled runtime:** Thread and turn requests use the approval and sandbox values accepted by the pinned Codex App Server (`untrusted`, `read-only`, and `workspace-write`).
- **Installer regression coverage:** The installed-payload smoke test now checks the daemon's persisted identity and authenticated health response.
- **Offline runtime bootstrap is native:** CrewAI provisioning begins in the desktop backend, independent of WebView startup, cached frontend state, or an existing credential-vault migration.
- **Native Windows sandbox ACLs work:** Each run uses the real per-logon SID from its suspended runner token, the installed runner receives the required execute permission, and PowerShell commands work under managed script-signing policies.
- **Repeated sandbox setup is non-interactive:** Once the native Windows sandbox is ready, repeated setup calls reuse the verified state instead of opening another UAC flow and rotating credentials.

## Root causes fixed

The local daemon serialized `creator_user_id` as `00000000-0000-0000-0000-000000000001`. Rust accepted that value, but the frontend UUID contract rejected it because the UUID has no valid version or RFC variant. Every persistent model path passed through the same run parser, so Codex, OpenRouter, Ollama, and other OpenAI-compatible providers appeared to fail in the same way.

The bundled Codex runtime also removed the legacy `unlessTrusted` approval variant and camel-case thread sandbox names. v0.3.4 pins the request values used by the installed runtime and adds regression coverage for both protocol contracts.

CrewAI bootstrap previously shared the credential-vault startup gate. A slow migration in an existing profile could therefore postpone offline runtime provisioning until after the installer's verification window. The runtime now starts in a native background worker immediately after its managed backend state is registered, while credential-dependent database and scheduling work remains gated as before. Cached Python extraction is also treated as incomplete when required interpreter files are missing, even if an older completion marker matches the bundled archive.

The v0.3.3 native sandbox passed a valid but intentionally unmapped per-run SID to `icacls`, which first attempted account-name resolution and failed. Windows App Capability and synthetic account SIDs are also rejected when added to this logon token by `CreateRestrictedToken`. v0.3.4 starts the runner suspended, reads its real per-logon SID, applies that SID directly to the approved DACLs through the Windows security API, and only then resumes the runner with the same SID in its restricted token. Temporary SID entries are removed when execution ends. The installed runner now has explicit read/execute access, PowerShell uses an encoded in-memory bootstrap instead of a policy-sensitive unsigned `.ps1` launch, and IPC reads close on the terminal frame.

The sandbox setup entry point previously launched its elevated helper on every call, even when the account, group, protected credential, capability seed, and setup marker were already valid. Repeated setup is now idempotent and returns the verified ready status before generating a password or invoking UAC.

## Installation and update integrity

- Windows: `LocalAI-Cowork-Setup-x64.exe`
- Linux: AppImage, DEB, and RPM packages
- In-app updates: signed Tauri updater artifacts and `latest.json`
- Verification: `SHA256SUMS`, CycloneDX SBOM, third-party notices, provenance, and GitHub attestations

> **Windows publisher notice:** Unless Authenticode credentials are configured for the release workflow, Windows may display "Unknown publisher." Verify `SHA256SUMS` and the GitHub artifact attestations before running the installer. In-app updater artifacts are independently protected by the mandatory Tauri updater signature.
