# Frozen settings on paired device agents

An optional `input.run_configuration` carries the copied `agent_config`, `access_mode` and `budgets`. It is validated before run admission. The device uses its own configured endpoint, model and credentials; a library template cannot replace them.

For the standalone model loop, copied instructions enter a system message, temperature reaches the OpenAI wire or Ollama `options`, and each model request uses the shorter of the copied timeout and the device owner's timeout. The requested output limit is sent to the provider. Run steps are capped by the device owner's `max_steps`; time, output and total token budgets are capped at the device's conservative defaults of 1,800 seconds, 4,096 output tokens and 262,144 total reserved tokens. The `run_started` event records the effective ceilings. These are local upper limits, so a remote actor cannot increase them.

Every model dispatch durably reserves its conservative wire context allowance plus bounded output. Missing provider usage never releases that reservation. Measured usage exceeding the reservation stops the run before returned tool calls execute. Final usage is `null` and `usage_complete=false` when any model response omitted counts; reported partial counts and reserved budget remain separately available. The result viewer labels incomplete consumption explicitly.

A copied tool filter narrows the actual available device catalog. Exact aliases `list_files`, `read_text_file` and `write_text_file` map to their workspace equivalents. Other unavailable names are rejected before effects. Server MCP aliases never expand into the broader device `mcp_call` tool. Read-only access retains only concrete workspace/source reads, bounded file searches and user input. Device human approvals and optional local consent remain required for actions, including when a copied setting requests autonomous access.

The standalone loop applies `execute`, `plan` and `hybrid`. Plan mode exposes no action tools. Hybrid performs a separate planning model request before execution; both requests consume the same run budget. Final structured output is requested only in the execution phase. Repeated tool failures can request human guidance; that guidance cannot authorize the skipped action. Copied command allow groups, command blacklist and tool-call ceilings are enforced before tool dispatch.

The installed Crew bridge accepts a small `agents[].agent_config` snapshot. Each role inherits and narrows the parent configuration, uses the device owner's locally bound model and tool grants, and receives only its selected frozen evidence. Role instructions, temperature, timeouts, mode and budgets reach its actual model callback. Hybrid planning is a separate bounded request. The original Crew tool and MCP grants remain an independent upper bound. Other nested configuration spellings are rejected rather than ignored. Crew execution requires the explicitly configured Python executable and the operator-qualified installed CrewAI version/source hash; this feature does not install that runtime.

MCP sampling inside a configured run uses the original device model and the active role's settings. Availability requires an actual original model context. Review of the MCP request, approval of one model use and approval before release remain separate. Sampling shares the run's deadline, step limit and conservative token reservation ceiling. A server MCP alias is never treated as permission to call an arbitrary device MCP server.

Direct Office requests are deterministic actions and do not call a model. They therefore do not consume generation instructions. They require the existing paired Office capability, applicable human/local approvals and an explicit tool filter that permits the requested Office family when a filter is present. Read-only and plan mode reject Office mutations before dispatch. The action consumes the configured tool-call ceiling. Office still requires its configured platform adapter and installed application.

Skill and memory IDs resolve only against the authenticated `frozen_runtime_context` delivered with the accepted run. Each selected entry must contain its original identity, revision, etag and definition; missing selections fail before dispatch. Roles can narrow that snapshot without looking up newer database content. An explicit empty selection removes that kind of evidence. Matching skill templates and run modes are applied from those original definitions. A device never obtains library content or authority from an ID alone.

The response journal retains original provider bytes before normalization, and an uncertain dispatch is never automatically replayed. Incomplete ordinary or sampling usage remains explicitly unknown. Hardware, real Office applications and an installed external Crew runtime require their own deployment qualification; the focused HTTP tests exercise actual device request propagation, timeout/no-replay behavior and hybrid phases without claiming those external installations are present.
