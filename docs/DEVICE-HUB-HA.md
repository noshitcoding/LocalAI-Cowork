# V2 device connections across API replicas

Device connections have one durable database owner. Migration 0043 stores the
executor, current credential/device revisions, API node, process boot nonce,
connection nonce, increasing epoch and a 20-second lease. A five-second renewal
revalidates the actual device credential. A competing replica cannot install a
second current owner. A restart makes a new connection after the old lease has
expired; it never adopts the old socket, desktop stream or run result.

The regular `/api/v1` WebSocket URLs stay unchanged. A desktop ticket may enter
any API replica. The receiving replica consumes the original one-use ticket and
checks the current user session, project/tenant permissions, active run/device
lease, credential revision and controller generation. For a different owner it
issues a 30-second, purpose-bound one-use routing grant and makes exactly one
HTTPS WebSocket handshake to the recorded owner. The owner consumes the grant
and independently checks those same live bindings. Agent reverse streams use
the durable pending stream record and a separate `agent` grant. No user session
token or agent bearer is copied to another replica. Both ends revalidate current
access and connection ownership every two seconds and close on shutdown or loss
of authority. An uncertain handshake is never retried or redirected.

Without explicit replica transport configuration, a local installation still
uses the database fence. A stream that reaches a different owner fails closed;
multi-replica desktop routing therefore requires the following configuration on
every API replica. Workers do not need this private listener.

## Private native HTTPS listener

Set `COWORK_DEVICE_HUB_CONFIG` to an absolute, private operator JSON file:

```json
{
  "format": 1,
  "origin": "https://api-replica-1.internal.example:43822/",
  "listen": "0.0.0.0:43822",
  "certificate_file": "/run/private/keys/device_hub_cert.pem",
  "key_file": "/run/private/keys/device_hub_key.pem",
  "ca_certificate_file": "/run/private/keys/device_hub_ca.pem"
}
```

The origin must route directly to this specific replica and its port must match
the private listener. Supply a certificate chain, one PKCS8 private key and the
trusted CA. Their files and the JSON must be ordinary, private operator-owned
files outside the served web tree: Unix 0600; Windows current-user/SYSTEM protected
DACL. Links/reparse points are refused. The listener exposes only the two private
grant handlers; it does not expose administration or general API credentials.
Allow TCP 43822 only between the installation's API replicas. TLS verification,
HTTP/1.1 and bounded WebSocket frames remain mandatory. There is no HTTP fallback,
environment proxy, redirect, automatic retry or certificate bypass.

`COWORK_DEVICE_HUB_NODE_ID` accepts an optional non-nil UUID for this API node.
Kubernetes uses the pod UID. Without it a fresh node UUID is generated; a separate
boot nonce always fences process restarts. The node identifier does not grant
device/user rights.

## Kubernetes API pods

For the provided HA Deployment use the optional `cowork-device-hub` Secret with
these keys: `device_hub.json`, `device_hub_cert.pem`, `device_hub_key.pem`,
`device_hub_ca.pem`, and `configuration_path` containing
`/run/private/keys/device_hub.json`. The private init step copies the selected
files into the operator key directory with UID1000/0600. The API container reads
the configuration path through an optional Secret reference; absence leaves the
extra listener disabled. Supply certificates through the operator's existing
certificate process. No issuer key is shipped or generated by the application.

For this topology set JSON `origin` to `kubernetes_pod_dns`. The API's Downward API
provides `COWORK_DEVICE_HUB_POD_IP`, `COWORK_DEVICE_HUB_NAMESPACE` and pod UID. The
native listener derives, for example,
`https://10-244-0-17.cowork.pod.cluster.local:43822/`. This mode requires IPv4 pods,
the conventional `cluster.local` DNS domain, CoreDNS `pods verified` for the
selected namespace, and a server certificate valid for
`*.cowork.pod.cluster.local`, issued by the installation's trusted CA. Custom DNS
domains and IPv6 installations should use an explicit directly routable HTTPS
origin and matching certificate instead. The templates do not alter cluster DNS
or install an issuer. Keep the optional Secret's sensitive fields in the existing
private deployment backup/restore process.

## Retention and operational verification

Pending stream routes expire after two minutes and are bounded to 32 per device.
Unused routing grants expire after 30 seconds; consumption remains recorded until
the bounded one-day cleanup window. At most4096 simultaneously active unused
grants are admitted, and at most100000 routing records are retained. No cleanup
modifies existing device run journals or results.
Graceful API stop drains its own streams and releases its exact connection lease;
process loss leaves the connection to expire in the database.

Compilation and local SQLite fences do not prove the installation's private DNS,
certificate issuance, network policy, shared PostgreSQL failover or behavior under
API/node loss. Production acceptance must observe a real client and agent whose
handshakes reach different API pods, revocation while streaming, owner loss, stale
nonce rejection and a fresh reconnect. Existing uncertain runs retain their
normal explicit recovery rules; replica routing does not replay their effects.
