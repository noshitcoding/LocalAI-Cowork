# LocalAI Cowork v0.3.9 private development snapshot

Status: private development build; not a published GitHub Release.

v0.3.9 makes OpenRouter profile deletion durable across application reinstallations and local-daemon reconciliation.

## Highlights

- **No profile resurrection:** Retired API profile IDs are honored by credential migration and by the local daemon before provider metadata is applied.
- **Complete deletion:** Deleting a profile now retires its database row before removing its secure credential, then tombstones daemon metadata and deletes the encrypted device binding.
- **Legacy Crew cleanup:** Empty, automatically generated OpenRouter Crew imports are no longer recreated. Existing unusable imports are retired and Crew, agent, and default selections move to a credential-bearing shared profile.
- **Consistent defaults:** A stale database default is moved to the valid replacement before the obsolete profile is retired.

## Compatibility and migration

No database schema or externally documented API changes are introduced. The existing profile retirement column remains authoritative. The startup repair never reads or logs credential values and keeps configured shared OpenRouter credentials in the operating-system credential store.

## Private build integrity

- Source branch: `codex/internal-development-v0.3.9` on the private internal remote
- Windows artifact: locally built `LocalAI-Cowork-Setup.exe`
- The local development installer is not Authenticode-signed and may display "Unknown publisher."
- This snapshot must not create a public tag, GitHub Release, updater manifest, or public package.

## Verification target

After upgrading from v0.3.8, the obsolete imported Crew profile is absent from the application and local daemon, the credential-bearing shared OpenRouter profile remains selected, and a Crew task proceeds beyond credential preparation.
