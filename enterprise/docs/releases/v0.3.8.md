# LocalAI Cowork v0.3.8 private development snapshot

Status: private development build; not a published GitHub Release.

v0.3.8 repairs OpenRouter crew profile migration after the v0.3.7 runtime transport fix.

## Highlights

- **Credential-aware crew migration:** A legacy Crew configuration without its own OpenRouter key no longer overrides a configured OpenRouter profile that has a securely stored key.
- **Automatic 0.3.7 recovery:** Existing Crew and agent selections that point to an automatically imported OpenRouter profile without a credential are repaired on startup.
- **Safe fallback selection:** The configured OpenRouter default is preferred when usable; otherwise another credential-bearing OpenRouter profile is selected without copying or exposing secret values.

## Compatibility and migration

No database schema or externally documented API changes are introduced. The repair runs during the existing credential initialization and preserves model overrides. Imported profiles with their own secure credential remain pinned as before.

## Private build integrity

- Source branch: `codex/internal-development-v0.3.8` on the private internal remote
- Windows artifact: locally built `LocalAI-Cowork-Setup.exe`
- The local development installer is not Authenticode-signed and may display "Unknown publisher."
- This snapshot must not create a public tag, GitHub Release, updater manifest, or public package.

## Verification target

After upgrading from v0.3.7, the affected Crew resolves to the existing credential-bearing OpenRouter profile and proceeds beyond provider credential preparation without an `OpenRouter API key is missing` failure.
