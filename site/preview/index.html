V2 // Preview preparation // 9 November 2026

A new foundation.
A clearly scoped preview.

LocalAI Cowork V2 brings a shared Rust core and web interface to the desktop workspace. The next version is 2.0.0-alpha.8. It is being prepared; no public V2 download is available from this page yet.

Choose your channel: existing public V1 downloads remain on v0.3.1. The reserved V2 release destination is v2.0.0-alpha.8; it becomes usable only after publication. An old V1 download is not the V2 preview.

What to evaluate in V2

01 / WORKSPACE

Model choice and visible approvals.

Projects, chat, selected file context, local Ollama or compatible hosted model endpoints, MCP tools and explicit execution plans.

02 / WORKFLOWS

Reusable steps with review.

Typed inputs, connected results, conditions, branches, relative waits and human review forms. Availability depends on configured tools and permissions.

03 / DOCUMENTS

Selected sources and checked results.

Guided document selection, source inspection, optional document engines, German/English OCR and editable extraction proposals. Review generated content before use.

04 / KNOWLEDGE

Project and personal context.

Topic folders, notes, imports and graphs from tags and sources. Automatic semantic entity extraction is still in development.

What remains experimental

  • Managed runtimes, registered runners, remote result retrieval and result adoption require additional service integration and installed-app acceptance.
  • The complete invoice/OCR/accounting chain, absolute workflow deadlines and event waits are not complete preview promises.
  • Windows document-engine paths have a preflight check; that check is not full long-path support.
  • Enterprise, Android, multi-device sync, identity-provider and container/cluster operation have separate deployment and acceptance requirements.
  • Signing, the update feed and recovery must be verified against the exact published package. No automatic V1-to-V2 update is promised.

Start with a separate profile

  1. Keep your current V1 installation and a backup of its data.
  2. After publication, select the V2 package on the explicitly versioned preview release page and verify its checksums and release notes.
  3. Use the V2 preview's own profile and non-sensitive copies of working files. Never point V2 at a V1 database.
  4. Choose the intended local sidecar or compatible self-hosted V2 server, then configure a model and the permissions needed for one small task.
  5. Review the plan, tool approval, resulting file and restart behavior before expanding usage.

Historical import is a separate reviewed operation. It does not reactivate old runs, credentials, approvals, schedules or outgoing operations. V1 remains the rollback application; V2 does not downgrade its database into a V1 profile.

Publication checklist

The preview will be published only with a reproducible source revision, passing release checks, fresh package receipts, checksums, a software bill of materials, exact signing/update status and installation/recovery results. Development test results qualify their tested source and scope; they are not a substitute for package acceptance.
