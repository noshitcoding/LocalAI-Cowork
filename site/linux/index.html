Linux x86_64 // V2 preview preparation

Check the platform.
Choose the package.

The next V2 preview targets DEB and AppImage on Linux x86_64. Its native baseline is glibc 2.39 or newer, with GTK 3 and WebKitGTK 4.1. An AppImage does not remove this glibc requirement.

Release channels: V2 2.0.0-alpha.8 is being prepared and is not published yet. The existing public V1 release is v0.3.1. These are separate applications and data profiles. Read the V2 preview scope.

V2 compatibility

Check your libc version with ldd --version. Ubuntu 24.04 is an example of the glibc 2.39 baseline; distribution name alone is not package acceptance. Older systems require an upgrade or a compatible source build. A Linux desktop session and the package's native library requirements are needed.

RPM, ARM64, macOS and musl-only distributions such as Alpine are outside this V2 desktop preview. Do not use earlier V1 instructions promising Ubuntu 22.04 compatibility or RPM packages for V2.

Install after publication

  1. Open the explicitly versioned V2 release destination after it has been published. Read its actual Linux acceptance result and download the DEB or AppImage asset and SHA256SUMS.
  2. Verify the exact downloaded bytes with sha256sum -c SHA256SUMS --ignore-missing. Keep the release notes and original package for recovery.
  3. For a DEB, replace <package.deb> with the downloaded filename and run sudo apt install ./<package.deb>. For an AppImage, run chmod +x ./<package.AppImage> and launch that exact file. Angle-bracket names are placeholders, not literal filenames.
  4. Launch using a fresh V2 profile and copies of working files; configure the local sidecar or a compatible V2 server explicitly.

Tools, permissions and updates

Ollama, optional document engines, external MCP servers and sandbox backends have their own setup requirements. The previous Python/CrewAI requirements are not a blanket V2 desktop dependency. No signed automatic-update feed is promised by this preparation page; the exact release notes must state whether updates are enabled and signed.

The public V1 v0.3.1 release page retains its own package inventory and requirements. It is separate from the V2 preview; use only instructions matching the downloaded version.
